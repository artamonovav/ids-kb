## Шаги воспроизведения

1. Открыть раздел «Права доступа» под пользователем с ролью «Оператор».
2. Выполнить действие, после которого раздел не обновляет данные.
3. Проверить ответ база данных в инструментах разработчика и журнале приложения.
4. Повторить операцию после очистки кэша браузера.

## Документация

В «Руководстве администратора», раздел «Права доступа», указано: **после изменения настроек раздел должен обновиться без перезагрузки**, а обращения к база данных должны логироваться с идентификатором запроса.

В «Спецификации API» для соответствующего метода зафиксирован ответ **200 OK и актуальные данные в течение 2 секунд**. Отклонение от этого поведения считаем дефектом, а не требованием поддержки.

## Локализация

Проблема воспроизводится стабильно на стенде. В журнале база данных видно:

```text
ERROR база данных: operation failed
area=Права доступа
traceId=4f2c9a7e-27374
```

По шагам удалось сузить область: ошибка возникает после действия, когда раздел не обновляет данные. В браузере запрос завершается кодом 500, в логах — исключение при обработке данных.

Причина: не учтён регистр в поиске.

## Варианты исправлений

- Нормализовать регистр при индексации.
- Добавить регрессионный тест на сценарий и проверку кода ответа.
- Проверить соседние сценарии раздела, чтобы исключить ту же причину.
