## Шаги воспроизведения

1. Открыть раздел «Экспорт данных» под пользователем с ролью «Оператор».
2. Выполнить действие, после которого раздел не применяет настройки.
3. Проверить ответ интеграционный адаптер в инструментах разработчика и журнале приложения.
4. Повторить операцию после очистки кэша браузера.

## Документация

В «Руководстве администратора», раздел «Экспорт данных», указано: **после изменения настроек раздел должен обновиться без перезагрузки**, а обращения к интеграционный адаптер должны логироваться с идентификатором запроса.

В «Спецификации API» для соответствующего метода зафиксирован ответ **200 OK и актуальные данные в течение 2 секунд**. Отклонение от этого поведения считаем дефектом, а не требованием поддержки.

## Локализация

Проблема воспроизводится стабильно на стенде. В журнале интеграционный адаптер видно:

```text
ERROR интеграционный адаптер: operation failed
area=Экспорт данных
traceId=4f2c9a7e-17971
```

По шагам удалось сузить область: ошибка возникает после действия, когда раздел не применяет настройки. В браузере запрос завершается кодом 500, в логах — исключение при обработке данных.

Причина: не обработано пустое значение.

## Варианты исправлений

- Добавить валидацию обязательных полей.
- Добавить регрессионный тест на сценарий и проверку кода ответа.
- Проверить соседние сценарии раздела, чтобы исключить ту же причину.
